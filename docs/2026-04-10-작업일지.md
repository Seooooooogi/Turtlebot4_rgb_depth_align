### 트러블슈팅

#### 1. depthai 2.28.0 API 호환성

| 문제 | 원인 | 해결 |
|---|---|---|
| `dai.node.Sync` 없음 | 2.28.0 미지원 | 두 개의 별도 XLinkOut 큐로 대체 |
| `dai.node.ImageAlign` 없음 | → 실제로는 지원됨 (버전 문제 아님) | 코드 유지 |
| `ALREADY_IN_USE` | 이전 프로세스 장치 점유 | udev 룰 설정 + `device.close()` 추가 |

#### 2. 카메라 루프 멈춤 현상

- **원인**: `create_timer` 콜백이 ROS2 executor 메인 스레드에서 실행 → CPU 스파이크 시 전체 루프 블로킹
- **해결**: 카메라 루프를 `threading.Thread(daemon=True)`로 분리

#### 3. 토픽은 있는데 데이터 없음

- **원인**: 두 큐를 각각 `tryGet()`으로 폴링 → 타이밍 불일치로 둘 다 None
- **해결**: `get()` (블로킹)으로 교체 → 프레임 도착 시까지 대기 후 처리

#### 4. 성능 개선

- `getCameraIntrinsics()` + `cv2.undistort()` 매 프레임 호출 제거
- `__init__`에서 `cv2.initUndistortRectifyMap()` 1회 계산 → `cv2.remap()` 사용

### Phase 2: 4m 거리 Depth 정밀도 분석

#### OAK-D Pro 스펙 확인 (데이터시트 + 판매 페이지)

| 항목 | 값 |
|---|---|
| Stereo baseline | 75mm |
| Stereo 센서 | OmniVision OV9282, 400P 운용 |
| 공식 Depth 범위 | **70cm ~ 12m** |
| IR dot projector | 940nm, 4700 dots, VCSEL |

#### 3m → 4m 오차 원인 분석

- 400P 기준 focal length ≈ 320px
- 3m에서 disparity ≈ 8px → 1px 오차 = **375mm**
- `HIGH_ACCURACY` 프리셋의 엄격한 LR-check가 중거리 center 픽셀을 reject → median이 배경 픽셀 참조 → 체계적 overestimate 가능성
- **대응**: `HIGH_DENSITY` 프리셋으로 변경, `stereo_subpixel: true` 활성화

#### 하드웨어 개선 적용

- IR dot projector 활성화 (`ir_dot_projector_intensity: 0.5`)
- IR dot / flood / stereo_preset 모두 YAML 파라미터화
- `stereo_preset` 런타임 전환 가능 (`HIGH_DENSITY` ↔ `HIGH_ACCURACY`)

### TurtleBot4 Bringup 구조 분석 (Phase 3 준비)

SSH(`ubuntu@192.168.1.13`)로 TurtleBot4에 직접 접속하여 확인했다.

#### Bringup 구조

```
standard.launch.py
├── robot.launch.py          (TurtleBot4 노드, Create3)
├── joy_teleop.launch.py     (조이스틱)
├── rplidar.launch.py        (라이다)
├── oakd.launch.py           ← 교체 대상
└── robot_description.launch.py (TF/URDF)
```

#### 기존 OAK-D 노드 특징

| 항목 | 내용 |
|---|---|
| 드라이버 | `depthai_ros_driver::Camera` (C++ composable node) |
| 파이프라인 | `i_pipeline_type: RGB` — **Depth 없음** |
| IR dot | `i_laser_dot_brightness: 100` |
| namespace | `ROBOT_NAMESPACE` 환경변수 |
